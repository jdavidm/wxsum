The broader resubmission remains incomplete: the paper is out of step with the code, required example/replication files are missing, and the new tests reproduce two implementation defects and a functional defect in the advertised longest-heat-spell calculation. Confirmed findings


B1. Failed saves replace the original data in memory

High. Confirmed command defect. Location: wxsum.ado:457-460; wxprep.ado:178-180 and 310-312.

All three paths commit the transformed dataset with restore, not before attempting save. A missing destination directory produces a save error, but datasignature changes and the original input is gone from memory. This contradicts the README/help promise that failure leaves data unchanged. Successful saves and existing-file rejection were separately tested and passed.

Reproduction: save_failure_atomic_wxsum; save_failure_atomic_prep_towide; save_failure_atomic_prep_tolong.

Recommended action: Attempt save while the preserved input can still be restored, and commit the in-memory result only after saving succeeds. Add the same failure-atomicity guarantee to both conversion paths. These are recommendations; the source was not edited.


B2. wxprep does not pad years to four digits

Low / date-domain edge case. Confirmed command defect. Location: wxprep.ado:442 and 508.

For an accepted daily date 1 January 0999, both towide and rename produce x_9990101 instead of x_09990101. Discovery in tolong and wxsum requires an eight-digit suffix, so the output violates the required naming format. The problem concerns historical year values, not the modern years in the bundled climate data.

Reproduction: prep_early_year_eight_digit_names; prep_rename_early_year.

Recommended action: Format the year with %04.0f in both name constructors and validate the supported year range; alternatively reject unsupported years explicitly before changing data and document the restriction.


B3. The advertised longest-heat-spell calculation can understate the answer

Medium. Confirmed functional contract defect: command/help inconsistency. Location: wxsum.sthlp:365-366; wxsum.ado:1228-1267.

For daily temperatures 35, missing, 35, 35, 20, 20 with heat_threshold(30), the real longest heat run is 2. The command returns heat_start=1, heat=0, heat_end=0 under the specified D3/D4 rules, so the advertised calculation max(heat_start,heat,heat_end) gives 1. The command does not directly return a global longest-run variable. Its three outputs follow their individual definitions, as confirmed by the 729-pattern tests, but they do not provide the global longest-run functionality promised by the help. This is a functional defect against that advertised contract, not merely an outdated example or a command correctly rejecting invalid syntax.

Reproduction: documented_longest_heat_formula.

Recommended action: To deliver the advertised functionality, compute and expose the true longest run anywhere in the window, which is 2 in this case, and test it with internal missing days. Preserve the separately defined mid-window statistic unless its semantics are deliberately revised. Removing or narrowing the help claim would instead withdraw or limit the advertised capability; that would not implement the missing global longest-run result.


B4. The manuscript describes the older interface and includes non-running examples

High / submission blocker. Confirmed manuscript/software mismatch. Location: sj paper/wxsum_body.tex:41-52,89,96,104,213-215,223-233,296-373.

The paper says wide is the default, omits required heat_threshold(), describes KDD as optional at a zero default, and omits wxprep, baseline(), observation-specific windows, heat spells, cuts(), minobs()/ref_min(), outstub(), and r() diagnostics. Its spell wording also predates the revised edge-missing and 0/1-break rules. Three temperature example blocks fail with r(198) for missing heat_threshold(). The submitted PDF was read alongside the TeX and is also the older presentation.

Reproduction: manuscript_example_2; manuscript_example_3; manuscript_example_4; manuscript_example_1/5/6 passed.

Recommended action: Update syntax, definitions, output tables/counts, narrative, all examples, and the compiled PDF together. Regenerate the article examples from a clean executable do-file and include their actual output.


B5. Required package and replication files are absent

High / distribution blocker. Confirmed packaging defect. Location: wxsum.pkg; README.md:140,155; wxsum.sthlp:464-466.

The package lists six absent paths: examples/rain_long.dta, examples/temp_long.dta, examples/hh_toy.dta, examples/wxsum_examples.do, examples/wxsum_examples.log, and examples/make_example_data.do. tests/run_all.do is also absent. The file checks produce nine failures because the example do-file/log are checked both as manifest entries and as explicit documentation promises; this is seven unique missing paths, not nine independent missing files.

Reproduction: Six package_file failures and three documented_file failures in results.csv.

Recommended action: Include the referenced files and original test/reference materials, verify the package from a clean local installation, and ensure the distributed paths match the documentation. This audit did not fetch replacement files from elsewhere.


B6. Several editorial writing and explanation requests remain unfinished

Medium / response completeness. Assessment from supplied evidence. Location: Editor E2/E3/E6/E8/E9/E11/E13 in requirements_matrix.csv.

The implementation substantially expands functionality, but the paper still needs a broader-use worked example, a substantive KDD explanation, explicit set maxvar guidance, the naming/rollback rationale, and forward-looking conclusions. Composite metrics and per-statistic naming were consciously not adopted in the plan; they need a clear explanation in the author response rather than a blanket completion claim.

Reproduction: Point-by-point source review; not treated as an executable software test.

Recommended action: Prepare a point-by-point response letter with explicit implemented, demonstrated, justified alternative, and deferred responses. Do not repeat the previous review's 100% completion statement.

Test design and results

The runner generated 67,567 assertion statements across 159 independently reported Stata cases. An assertion can apply to several observations, and cases stop at their first failing statement, so this is a generated-check count rather than a claim that every assertion executed. Cases run in one fresh batch Stata session with this folder first on adopath and set type double. Synthetic numerical checks use tolerance 1e-9 * max(1,abs(expected)); missing results are tested explicitly. Temperature CSV expectations are converted to the DTA input's binary32 precision before calculating expected statistics.

The group table below includes both executable Stata cases and the packaging file checks. Its total is therefore 174 checks, rather than 159 Stata cases.

The 40 oracle cases passed: two exhaustive spell cases cover all 729 six-day combinations of missing/spell/break values for each of rain and heat; 38 independently computed numerical cases cover both types, six years and 12 units, long and wide output, calendar and cross-year windows, leap days, fixed and rolling references, varying-length unit windows, partial coverage, missing dates, and positive/negative event lags. Python scalar/date/statistics routines provide the oracle; these fixtures are loaded directly rather than being constructed through wxprep.

Additional cases test hand-calculated statistics, minobs/ref_min, zero reference variance, all-missing/singleton/constant windows, threshold equality, daily temperature bins 1/2/4/42, arbitrary cuts, GDD categories/labels, stored results and characteristics, string keep variables, output collisions, invalid options, save/replace, forced rollback, all wxprep date forms, daily aggregation, duplicate handling, filtering, exact round trips, maxvar rejection, Kelvin conversion, and a toy merge/regression. The manuscript's six example blocks were extracted and run with data paths redirected to the supplied folder and the save target redirected to a tempfile; the wxsum syntax was preserved.

Bundled DTA tests run sample and full rain/temperature data. Independent CSV-derived expectations verify every core statistic for the ten shared sample units over May 15–October 15, 2003–2023. The CSV files are larger histories than the small DTA examples, not exact file-format duplicates. Full-history and sample cross-year runs also passed. Both calendar and unit-specific 12,000-by-366-day tests cross the engine's four-million-cell chunk boundary and passed.

How to rerun and inspect failures

From the extracted audit directory, run the following command using Python 3.10+ and a licensed Stata executable:

python run_tests.py --source "C:\Users\annal\Downloads\wxsum" --stata "C:\Program Files\StataNow19\StataMP-64.exe"

The runner uses the Python standard library and never installs anything or changes the source folder. It writes generated fixtures, .do cases, logs, CSV/JSON results, and source hashes under verified_results/. It returns exit status 1 while any regression or packaging check fails and 0 only when the run completes with every check passing. A nonzero status in this delivered run is expected. Output files are overwritten on a rerun; use --results with another directory to preserve this run.

verified_results/run_all.do can rerun the already generated suite directly in Stata on this computer. For another computer or extraction location, use the Python runner first to regenerate its absolute file paths. Individual cases can be rerun after setting adopath to the source folder. The full text log preserves command output; failure_excerpts.txt gives compact reproductions. requirements_matrix.csv maps each request to evidence. source_inventory.json pins the exact audited files.


Limits of the conclusion

Passing cases show that the tested v6 calculations agree with independently computed expectations; they cannot prove that no other bug exists. This run used StataNow/MP 19.5 only; the advertised Stata 15/15.1 compatibility, other operating systems/editions, interactive user breaks, file-lock/disk-full races, every possible weather-value range, and every physical composite definition were not certified. No remote install was attempted. Local manifest completeness was tested; a clean distribution install still needs to be rerun after its missing files are supplied. The full PDF was read for content; its visual typesetting and TeX compilation were outside this code/compliance audit.

The original package was not changed. The next substantive work is to correct B1/B2, resolve the missing longest-run functionality in B3, supply the missing replication package, update the paper/PDF and examples, then rerun this suite and prepare the point-by-point response letter.
